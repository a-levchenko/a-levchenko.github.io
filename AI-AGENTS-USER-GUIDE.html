Before you start

What you need in front of you

Gather these four things first. If you are missing one, ask the person who invited you to the workshop — none of them is something you can work out for yourself.

A Windows laptopWith permission to install software. If your company locks that down, ask IT first — installing takes five minutes, getting permission can take days.
Two GitHub linksOne for the Salesforce project, one for the AI agent setup. They look like https://github.com/company/project.git. You will paste both into this page in Part 2.
A GitHub accountWith access to both of those. Test it: open both links in a browser. If you see the files, you are fine. If you see "404", you do not have access yet.
A Salesforce practice orgA free Trailhead Playground works. You need its username and password — not the login you use for your company's real Salesforce.
One rule above all othersNever point this at your company's live Salesforce. The agents refuse to work against a live system, with no way to override it — but the safest arrangement is for those credentials not to be on the laptop at all.

Set aside about 45 minutes for Parts 1 to 3. You only ever do them once.

Part 1

Install the tools

Seven things to install. Each step is the same shape: run a command, then check it worked. If a check fails, open the "something went wrong" note underneath it.

How to open a terminal. Press the Windows key, type powershell, and press Enter. A blue or black window opens where you can type commands. That window is called a terminal. Keep it open for all of Part 1.

Node.js

The engine that runs the agent's helper scripts. Install this one first.

in your terminal
winget install OpenJS.NodeJS.LTS
Then close the terminal and open a new oneNewly installed tools only appear in a terminal that was opened after the install. This trips up almost everyone. Close the window, open PowerShell again, and continue.
check it worked
node -v
You should seeA version number starting with v20 or higher, like v22.21.1.

Git

Keeps every version of the work and shares it with your team. The agents use it constantly; you will barely touch it.

in your terminal
winget install Git.Git
new terminal, then check
git --version
You should seeSomething like git version 2.42.0.windows.2.

The Salesforce command line

How the agents talk to your Salesforce — installing work into it, running tests, reading how it is configured.

in your terminal
npm install -g @salesforce/cli

This one takes a minute or two and prints a lot of text. That is normal.

new terminal, then check
sf --version
You should seeA line starting with @salesforce/cli/ and a version number.
npm is not recognised?

That means Node.js from step 1 is not installed, or you are in a terminal that was open before you installed it. Close the terminal, open a new one, and try node -v first.

The code inspector

An add-on for the Salesforce command line that automatically checks every file the agents write for security holes and sloppy patterns.

in your terminal
sf plugins install code-analyzer
You should seeIt finishes without an error. If it asks you to confirm installing from an unverified publisher, answer y.

Java

You will never use it directly. Part of the code inspector needs it to run.

in your terminal
winget install EclipseAdoptium.Temurin.21.JDK
new terminal, then check
java -version
You should seeThree lines mentioning a version number and "Temurin" or "OpenJDK".

Microsoft Word

Not something you install here — you almost certainly have it. The agents write your design document and the two handover guides as real Word files, by driving Word itself.

Just checkOpen the Start menu and type Word. If Microsoft Word opens, you are done. Close it again.
If you do not have WordA task will stop at the first document it tries to write. This is the one thing on the list that cannot be installed automatically — ask IT.

VS Code, and the Claude extension inside it

VS Code is the window where everything happens. The Claude extension is the agent itself.

in your terminal
winget install Microsoft.VisualStudioCode

Then open VS Code and add the extension:

  • Click the Extensions icon in the left-hand icon strip — four small squares.
  • Type Claude Code in the search box.
  • Click Install on the official Anthropic one.
  • Sign in when it asks, using the Claude account you were given.
You should seeA new Claude icon appears in the icon strip, and clicking it opens a chat panel.

Sign in to GitHub — recommended

Does your signing-in for you, so Git never stops to ask for a password.

in your terminal
winget install GitHub.cli
new terminal, then sign in
gh auth login

Answer: GitHub.com → HTTPS → Yes (authenticate Git) → Login with a web browser. Copy the code it shows, press Enter, and paste the code into the browser page that opens.

You should see✓ Logged in as yourname back in the terminal.

Tell Git who you are

Every save is signed with your name. Put your own name and work e-mail in, replacing the examples.

in your terminal
git config --global user.name "Your Name"
git config --global user.email "you@yourcompany.com"
CheckRun git config --global user.name — it should print your name back.
Part 2

Get the project onto your computer

The Salesforce project and the AI agent setup start life as two separate GitHub repositories. They have to end up as one folder on your laptop. This part does that.

Paste your two links here first

Every command below will fill in with your real values, so you can copy them straight across. Nothing leaves this page — it is only stored in your browser.

folder it creates: salesforce-project
downloads into: ai-base-download

Which of these are you?

Then you have almost nothing to do. The agent setup is already part of the Salesforce project, so one download gets you everything.

Make a folder to work in, and go into it

in your terminal
mkdir C:\Work
cd C:\Work

If it says the folder already exists, that is fine — the cd line still works.

Download the project

in your terminal
git clone <repo 1 link>
You should seeResolving deltas: 100% and then done. You now have a folder C:\Work\salesforce-project.

Check the agent setup really is in there

in your terminal
cd C:\Work\salesforce-project
dir
You should seeBoth sfdx-project.json and CLAUDE.md in the list. If CLAUDE.md is missing, the setup was never combined — switch to "I am the first one" above.

That is Part 2 finished. Skip to Part 3.

What you are about to do. Download both repositories side by side, copy the agent setup into the Salesforce project, and save that combination back to GitHub. After this, everyone else on your team only needs the one download in the other tab.

Make a folder to work in, and go into it

in your terminal
mkdir C:\Work
cd C:\Work
What does cd do?

A terminal is always "standing in" one folder. cd means change directory — it walks into a folder, so the next commands act on that folder. You will do this a lot.

Download the Salesforce project

in your terminal
git clone <repo 1 link>
You should seeA new folder C:\Work\salesforce-project.

Download the AI agent base next to it

The extra words at the end give it a clear name, so you do not confuse the two folders.

in your terminal
git clone <repo 2 link> ai-base-download
You should now have two foldersC:\Work\salesforce-project and C:\Work\ai-base-download.

Look inside the download — there are two possible shapes

in your terminal
dir C:\Work\ai-base-download

Read what it prints and pick one:

  • You see CLAUDE.md listed → the setup is at the top level. Use command A in the next step.
  • You see a folder called ai-base → the setup is one level down. Use command B in the next step.

Copy the agent setup into the Salesforce project

Use the one command that matches what you saw in step 4.

command A — CLAUDE.md at the top
robocopy C:\Work\ai-base-download "C:\Work\salesforce-project" /E /XD .git
command B — there is an ai-base folder
robocopy C:\Work\ai-base-download\ai-base "C:\Work\salesforce-project" /E
Do not drag the folders in File ExplorerSome of what you are copying is hidden — a folder called .claude that Windows does not show you by default. Drag-and-drop will silently miss it and nothing will work. The command above copies hidden items properly.
You should seeA summary table ending in numbers. Robocopy prints a number instead of "success" — anything from 0 to 7 means it worked. 8 or above means a real failure.
What is /XD .git for?

Each downloaded folder has a hidden .git folder holding its entire history. If you copied the agent base's one over the Salesforce project's one, you would wreck the project's history. /XD .git tells the copy to leave it alone. Command B does not need it, because the ai-base folder does not contain one.

Check the two are now one

in your terminal
cd C:\Work\salesforce-project
dir
dir .claude
You should seesfdx-project.json and CLAUDE.md side by side in the first listing, and agents, hooks, scripts, skills in the second. If dir .claude says the path cannot be found, the copy missed the hidden folder — run step 5 again.

See what you are about to save

in the project folder
git status
You should seeA list of new files in red, under "Untracked files" — CLAUDE.md, docs/, .claude/, agent-memory/ and so on. These are exactly the files you copied in. Nothing should be listed as deleted.

Save it back to GitHub, on its own branch

A branch is a safe side-copy. Your team reviews it before it becomes official, exactly as they would any other change.

in the project folder
git switch -c chore/add-ai-agent-base
git add .
git commit -m "Add the AI agent base"
git push -u origin chore/add-ai-agent-base
You should seeGit prints a link to open a pull request. Open that link in a browser, click Create pull request, and ask your team to merge it.
After it is merged, everybody else on the team just downloads the project the normal way and gets the agent setup with it. Nobody has to repeat Part 2.

Tidy up

The download folder has done its job. You can delete it in File Explorer, or leave it — it does no harm.

optional
Remove-Item -Recurse -Force C:\Work\ai-base-download
Part 3

Open it and connect everything up

From here on you can forget PowerShell. Everything happens inside VS Code.

Open the project folder — the folder, not a file

  • Open VS Code.
  • File → Open Folder…
  • Choose C:\Work\salesforce-project and click Select Folder.
  • If it asks "Do you trust the authors of the files in this folder?", click Yes, I trust the authors.
Open the right folderNot the folder above it (C:\Work), not force-app inside it. The agents look for their instructions in whatever folder you opened. Open the wrong one and they will not find them — this is the single most common first-day mistake.
You should seeIn the left panel: CLAUDE.md, sfdx-project.json, docs, force-app, agent-tasks.

Open the terminal inside VS Code

From the top menu: Terminal → New Terminal. A panel opens along the bottom.

Why this matters more than it sounds. Salesforce commands only work when the terminal is standing in the project folder — the one holding sfdx-project.json. VS Code's own terminal always opens there. That is the whole reason to use it instead of PowerShell from now on.
confirm where you are standing
pwd
You should seeYour project folder path, ending in the project name — not C:\Users\you and not C:\Work.
What if I see "This directory does not contain a valid Salesforce DX project"?

You are standing in the wrong folder. Run pwd to see where you are, then cd into the project folder. Or simply close the terminal panel and open a fresh one with Terminal → New Terminal, which always starts in the right place.

Let the project check your laptop

The project ships with its own checker. It tells you in one go whether everything from Part 1 is present and usable.

in the VS Code terminal
node .claude/scripts/check-tools.js
You should seeOK next to every line: node, git, sf CLI, code-analyzer, java, Microsoft Office.
Something says MISSING

Run the same command with --install on the end — it will try to install what is missing and check again. Microsoft Office is the exception: it is never installed automatically, so a missing Word has to be solved by you or IT.

It says it cannot find the file

You are in the wrong folder. See step 2 — that path only works from the project folder.

Connect your practice Salesforce

workshop is just a nickname for the connection. Keep it as-is and everything else in this guide will match.

in the VS Code terminal
sf org login web -a workshop

A browser window opens on the Salesforce login page. Sign in with your practice org username and password, then click Allow.

make it the default, then check
sf config set target-org workshop
sf org display -o workshop
You should seeYour username, an org ID, and Connected Status: Connected.

Check Git can reach GitHub from here

in the VS Code terminal
git fetch
You should seeNothing at all, or a few lines about branches. No password prompt, no error. Silence is success here.
It asks for a username and password

Go back to Part 1 step 8 and run gh auth login. That stores your sign-in once so Git stops asking.

Open the Claude panel and set it to Auto

  • Click the Claude icon in the left-hand icon strip.
  • Set the permission mode to Auto. Look for the mode indicator at the bottom of the panel, or type /config.
  • Type /agents and press Enter.
You should seeFour agents listed: solution architect, solution critic, developer, code reviewer. Typing / should also offer sf-task, sf-plan and sf-review.
Is "Auto" safe?

Yes, and it is required — the agent has to edit files, install things into your practice Salesforce and save its work dozens of times per task, and stopping to ask you each time would make it unusable. Your safety net is elsewhere: genuinely destructive commands are blocked outright and cannot be unblocked, you approve the plan before anything is built, a separate reviewer checks the finished work, and it never touches your live Salesforce.

Setup finished

You never have to do Parts 1 to 3 again. From now on you open VS Code, open this folder, and start typing.

Part 4

Run your first task

Five things happen, and you are only needed for the first three. Everything is typed into the Claude panel, not the terminal.

Describe what you want, in your own words

Click into the Claude panel and type. Start with /sf-task and then just explain the job the way you would to a colleague. No technical words needed.

in the Claude panel — an example
/sf-task Our office lends equipment to employees — laptops, projectors, tools.
Today it is a spreadsheet at reception and things go missing. We want a register
of what we own, who has what right now, and a simple screen where reception can
hand an item out and take it back. Reception should see which items are overdue.
An item that is already out must not be handed out again until it is returned.
Task: WS-001. Org: workshop. Base branch: main.

The last line is optional detail that saves questions later:

Task:Any reference number you like. It names the folder your paperwork goes into.
Org:The nickname from Part 3 — workshop.
Base branch:Which version of the project to start from. Usually main. Ask your team if unsure.

Leave any of them out and you will simply be asked.

Answer the interview

You get a series of multiple-choice questions about your business — never about technology. The suggested answer comes first and is marked. Pick with the arrow keys and Enter, or click. There is always an Other if nothing fits.

Expect to be asked: who uses it, what they do step by step, what must never happen, how much data, what you explicitly do not want, and how you will check it works.

This is where you keep the work small. Every "no, we don't need that" here removes a whole chunk of building. Be decisive.

Confirm the write-up, then approve the plan

Two checkpoints, a little while apart.

  • First, your answers are read back as a short summary. Say yes, or say what is wrong.
  • Then — after it has investigated your Salesforce and designed something — you get a short plan to approve. Read the section called "what it will not do" carefully. That is where things you might have wanted were deliberately left out.
  • Choose Approve, Change something, or Show me the technical detail. Looking at the detail approves nothing — it is safe.
Nothing is built before you approveAnd once you do, you are not needed again until it is finished.

Leave it alone

It now builds, installs into your practice Salesforce, tests, reviews its own work and writes the handover documents. A small task takes an afternoon. You can close the laptop lid — but do not close VS Code while it is working.

Lines scroll past showing what it is doing. You do not need to read them.

Read the report, then try it yourself

You get a plain-language summary of what a user can now do, how it was checked, where the guides are, and anything to know before it goes live.

  • Open your practice Salesforce and walk through the thing you asked for. Five minutes of clicking is worth more than any report.
  • Open the user guide it wrote — it should describe something you recognise.
  • Hand it to your developers for the real release. The agents stop at your practice org, always.
Part 5

The commands you will use

Four, and you will mostly use the first. All typed into the Claude panel.

/sf-task + your descriptionThe full job: questions, design, your approval, build, test, review, handover. This is the one.
/sf-task WS-001Just the reference number — picks up a task that was interrupted, or builds a design you agreed earlier. It works out by itself how far it got.
/sf-plan + your descriptionQuestions and a design only — then it stops. Use it to agree an approach, or size something, before committing to the build.
/sf-reviewReviews whatever is on your branch against the project's standards. Works on hand-written code too.
/sf-task WS-001 --restartThrows a task away and begins again. It shows you exactly what will be deleted and waits for you to type yes.
If you close VS Code mid-task, nothing is lost. Reopen the project and type /sf-task with just the reference number.
Part 6

Where your files end up

One folder per task, named after your reference number, inside agent-tasks. You can open any of it from the file list on the left of VS Code.

requestYour own words, kept exactly. Your request, every question and answer, and the scope you confirmed.
designWhat it found in your Salesforce, the plan you approved (as a Word file), the criticism it survived, and the full technical design.
planThe build broken into ordered pieces.
dataOptional — samples and evidence that are not documents.
deploymentFor whoever moves this to the live system: exactly what to move, and anything that must be done by hand.
docsTwo Word guides ready to hand over — one for administrators, one for the people who will use it.
The two you will actually open: design/design-brief.docx when you are asked to approve, and docs/user-guide.docx at the end.
Part 7

If something breaks

Nearly everything that goes wrong is one of these. Click the one that matches.

"sf is not recognised" / "node is not recognised" / "git is not recognised"

The tool is installed but this terminal window does not know about it yet. Close the terminal and open a new one. In VS Code: click the bin icon on the terminal panel, then Terminal → New Terminal.

If a new terminal still does not recognise it, the install did not finish — run the install command from Part 1 again and watch for errors.

"This directory does not contain a valid Salesforce DX project"

Your terminal is standing in the wrong folder. Run pwd to see where it is. It must be the folder containing sfdx-project.json.

Quickest fix: close the terminal panel and open a fresh one — VS Code always starts it in the folder you opened.

"Cannot find module .claude/scripts/check-tools.js"

Same cause as above — wrong folder, or you opened the wrong folder in VS Code. Check with dir that you can see CLAUDE.md. If you cannot, use File → Open Folder… and pick the project folder itself.

The agent cannot find CLAUDE.md, or /sf-task is not offered

Either you opened the wrong folder in VS Code, or the agent setup was never copied in. In the file list on the left you must be able to see CLAUDE.md and sfdx-project.json together.

If CLAUDE.md is missing, go back to Part 2 and follow the "I am the first one" path.

I copied the files but .claude is not there

You almost certainly dragged the folders in File Explorer, which skips hidden items. Run the robocopy command from Part 2 step 5 — it copies hidden items correctly.

To see hidden items in File Explorer: View → Show → Hidden items.

I pushed to GitHub but .claude is not on the website

The Salesforce project probably has a rule telling Git to ignore those files. Open the file called .gitignore in the project and look for a line mentioning .claude. Remove that line, then run the git add, git commit and git push steps again.

Git keeps asking for a username and password

Run gh auth login (Part 1 step 8). Choose GitHub.com → HTTPS → Yes → Login with a web browser.

If your company uses single sign-on, GitHub may also need you to authorise your access once. The error message contains a link — open it and click Authorize.

The agent says my Salesforce is a production org and stops

You connected the live system instead of a practice one. This is deliberate and cannot be overridden. Connect a practice org instead:

sf org login web -a workshop then sf config set target-org workshop.

It stopped and is asking me something

That is normal and not an error. It stops rather than guess. You will get a specific question with options and their consequences — answer in the same chat and it carries on from where it stopped.

It says Word or Office is not available

The design document and the handover guides are produced through Microsoft Word itself. Without desktop Word installed, a task stops at the first document. There is no workaround in the project — it needs a real Word installation.

A command printed a wall of red text

Read the first few lines, not the last. The first line is usually the actual problem; everything after it is noise.

If it is still unclear, paste the whole thing into the Claude panel and ask what it means. That is a perfectly good use of it.

Part 8

Words you will hear

You do not need to use any of these. You will see them scroll past, and it helps to know they are ordinary things with intimidating names.

Terminal

The text window where you type commands. Always "standing in" one folder — which folder matters, because commands act on it.

Repository (repo)

A project stored on GitHub, with every version of every file it has ever had. You download a copy; your copy stays linked to the original.

Clone

Downloading a repository to your laptop for the first time.

Branch

A safe side-copy where work happens, so the team's main version is never disturbed until the work is finished and reviewed.

Commit · push

A commit is a labelled snapshot of your work. A push sends your snapshots to GitHub for the team. The agents do both for you, after every stage.

Pull request

Formally proposing that your branch be folded into the team's main version. A human opens it, reviews it, and approves it.

SFDX project

A Salesforce project laid out in the standard way, with a file called sfdx-project.json at the top. That file is how the tools know the folder is a Salesforce project.

Org

One Salesforce system. Your company has several — a live one and practice copies. The agents only ever work in a practice one.

Production

The live Salesforce the business runs on. Strictly off limits to the agents, with no override.

Deploy

Installing the finished work into a Salesforce system so it actually exists there and can be used.

Metadata

The shape of your Salesforce — fields, screens, rules, permissions. As opposed to the data, which is the actual records.

Object · field

An object is a kind of thing you store — an item of equipment, a loan. A field is one piece of information about it — its asset tag, its due date.

Apex

Salesforce's programming language. Used when a rule is too complex to configure by pointing and clicking.

Flow

Automation built by configuring rather than programming. Preferred where it is enough, because an administrator can change it later.

LWC

Lightning Web Component — a custom screen, for when the standard Salesforce layouts will not do.

Permission set

A bundle of access rights granted to particular people. "Reception can use the loan screen" is a permission set.

Test coverage

How much of the new code the automated tests actually exercise. Salesforce refuses work into a live system below a set threshold.

Static analysis

An automatic inspection for known bad patterns — security holes, inefficiency — without running anything.
